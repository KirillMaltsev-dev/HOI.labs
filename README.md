# Лабораторная J3 — асинхронный обход HTTP-сервера

Программа собирает сообщения со всех достижимых ресурсов сервера, начиная с `/`,
и выводит их в лексикографическом порядке. Задание находится в
[docs/Task_J3.pdf](docs/Task_J3.pdf), предоставленный сервер — в
[docs/Task_J3-server.jar](docs/Task_J3-server.jar).

## Требования и сборка

Нужен **JDK 21**: проверьте `java -version` и настройку `JAVA_HOME`.
Maven Wrapper при первом запуске скачивает Maven 3.9.16 и зависимости;
отдельно устанавливать Maven не требуется. Библиотеки: Jackson для JSON,
JUnit Jupiter для тестов. Preview-возможности Java не используются.

Из корня проекта в PowerShell:

```powershell
.\mvnw.cmd clean package
```

В Linux/macOS используйте `sh ./mvnw clean package`.
Исполняемый JAR со всеми зависимостями появится в `target/lab_j3.jar`.

## Запуск сервера и клиента

В первом терминале запустите предоставленный сервер. Замените `FirstLast`
своими именем и фамилией, записанными подряд латиницей: эта строка определяет
индивидуальный набор данных.

```powershell
java -jar docs/Task_J3-server.jar FirstLast
```

Сервер занимает порт 8080. Во втором терминале запустите клиента:

```powershell
java -jar target/lab_j3.jar
```

Адрес по умолчанию — `http://localhost:8080/`. Его можно передать явно:

```powershell
java -jar target/lab_j3.jar http://localhost:8080/
java -jar target/lab_j3.jar --help
```

**В предоставленном JAR есть ошибка:** передача порта вторым аргументом
обычного запуска вызывает `ClassCastException`, поскольку порт остаётся строкой.
Если 8080 занят, используйте следующий запуск на другом свободном порту.
Он вызывает ту же точку входа с числовым аргументом, не изменяя JAR:

```powershell
java -cp docs/Task_J3-server.jar clojure.main -e '(require (quote server)) (server/-main (name (quote FirstLast)) 18080)'
```

Тогда адрес клиента:

```powershell
java -jar target/lab_j3.jar http://localhost:18080/
```

Сервер работает до остановки через `Ctrl+C`.

## Результат и ошибки

В `stdout` записываются только отсортированные сообщения: одно на строку,
в UTF-8. Сообщение корня, одинаковые тексты и пустые сообщения сохраняются;
пустое сообщение выглядит как пустая строка. Порядок определяется
`String.compareTo`: учитываются регистр и значения символов, языковая
сортировка не применяется.

Количество сообщений и время обхода выводятся отдельно в `stderr`:

```text
Collected 1001 messages in ... seconds.
```

Чтобы сохранить сообщения без диагностик, можно перенаправить стандартный
вывод. В PowerShell 7.4+:

```powershell
java -jar target/lab_j3.jar http://localhost:18080/ > messages.txt
```

В Windows PowerShell 5.1 для сохранения исходных UTF-8 байтов используйте
перенаправление через `cmd`:

```powershell
cmd /c "java -jar target/lab_j3.jar http://localhost:18080/ > messages.txt"
```

Коды завершения:

| Код | Значение |
| --- | --- |
| `0` | Обход завершён успешно либо показана справка |
| `1` | Ошибка запроса, ответа или прерывание обхода |
| `2` | Некорректные аргументы командной строки |

Клиент принимает корневой HTTP/HTTPS URL без имени пользователя, query и fragment.
Тайм-аут подключения — 5 секунд, запроса — 30 секунд. При ответе, отличном от
HTTP 200, неверном JSON или тайм-ауте оставшиеся запросы отменяются; в диагностике
указывается проблемный URL. Повторов запросов нет. Сообщения начинают выводиться
только после успешного полного обхода, поэтому ошибка не выдаёт частичный набор
за готовый результат.

## Как устроен обход

Сервер возвращает JSON:

```json
{"message": "some text", "successors": ["42", "99"]}
```

Здесь `42` и `99` — пути `/42` и `/99` того же сервера. Пустой список означает,
что у ресурса нет следующих узлов. URL рассматриваются как вершины графа,
а ссылки из `successors` — как его рёбра.

1. Координатор отмечает корневой URL как запланированный и запускает его запрос.
2. Каждый запрос выполняется блокирующим `HttpClient.send()` в отдельном
   виртуальном потоке из `newVirtualThreadPerTaskExecutor()`.
3. Через `ExecutorCompletionService` координатор получает готовый ответ,
   сохраняет сообщение и сразу запускает запросы к ещё не посещённым путям.
4. Счётчик незавершённых задач увеличивается при запуске запроса и уменьшается
   при обработке его результата. Ноль означает завершение полного обхода.
5. Координатор сортирует собранный список и передаёт его точке входа для вывода.

Множество посещённых URL, счётчик и список сообщений принадлежат одному
координатору. Рабочие задачи их не меняют, поэтому блокировки общих коллекций
не нужны. Повторные ссылки и циклы не вызывают повторного запроса. Завершение
одной медленной ветки не мешает продолжать другую.

Классы в `src/main/java/ru/nsu/maltsev/j3`:

| Класс | Назначение |
| --- | --- |
| `Main` | Аргументы, запуск, вывод, коды завершения |
| `Crawler` | Координация обхода, учёт URL, сортировка и отмена задач |
| `PageClient` | Контракт получения одной страницы, позволяющий тестировать граф отдельно от сети |
| `HttpPageClient` | Общий HTTP-клиент, тайм-ауты, проверка и разбор JSON |
| `Page` | Неизменяемые сообщение и список следующих путей |

В выданном сервере 1000 пронумерованных ресурсов и корень: всего **1001 сообщение**.
Ресурсы распределены по десяти уровням, на каждом задержка не превышает 12 секунд.
Сумма максимальных задержек по уровням — 120 секунд. Это ориентир для времени
эффективного обхода с небольшими накладными расходами, а не нижняя граница:
максимальные задержки разных уровней могут приходиться на разные ветви.
Фактический минимум определяется самой долгой последовательной цепочкой запросов
и зависит от идентификатора студента. Отдельный запрос на 12 секунд укладывается
в тайм-аут 30 секунд; тайм-аута 30 секунд на весь обход нет.

## Проверки

Быстрые тесты:

```powershell
.\mvnw.cmd test
```

Они проверяют обход ветвлений и циклов, однократное посещение URL, сортировку,
сохранение одинаковых и пустых сообщений, виртуальные потоки, независимое
продвижение ветвей, UTF-8, ошибки HTTP/JSON, тайм-ауты, прерывание и отмену
реальных HTTP-запросов. Тесты используют подставной граф и локальный HTTP-сервер
на автоматически выбранном порту, без внешних сервисов.

Полная проверка с предоставленным JAR выполняется отдельно и обычно занимает
около полутора-двух минут:

```powershell
.\mvnw.cmd -Pserver-it verify
```

Можно указать свой идентификатор для сервера:

```powershell
.\mvnw.cmd -Pserver-it '-Dserver.studentId=FirstLast' verify
```

Тест `ProvidedServerIT` выбирает свободный порт, запускает оригинальный сервер
и собранный `target/lab_j3.jar`, проверяет успешное завершение, 1001 сообщение
и сортировку. После проверки тест завершает запущенные им процессы.
Ограничение 180 секунд относится только к этому тестовому прогону.

Результаты полного прогона сохраняются в `target/`:

- `provided-server-messages.txt` — сообщения клиента в UTF-8;
- `provided-client.log` — статистика и ошибки клиента;
- `provided-server.log` — вывод сервера;
- `provided-server-result.txt` — идентификатор, количество сообщений и время;
- `failsafe-reports/` — отчёт интеграционного теста.

### Результат контрольного прогона

Проверено 19 октября 2026 года на Java 21 с идентификатором `IntegrationTest`:

- Все **44 быстрых теста** и **1 интеграционный тест** прошли.
- Собранный JAR получил **1001 сообщение за 91,256 секунды**.
- Отдельная сверка с графом, сгенерированным исходным сервером для того же
  идентификатора, подтвердила точное совпадение всего отсортированного списка,
  включая повторяющиеся и пустые сообщения.
- Сумма задержек на критическом пути этого графа — **90,554 секунды**:
  измеренное время близко к минимально возможному для данного набора данных.

Время зависит от идентификатора студента и условий выполнения.
